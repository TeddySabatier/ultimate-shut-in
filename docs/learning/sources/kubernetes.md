# Kubernetes: curated sources

Compiled 2026-10-23. Every URL below was opened and checked on that date. Current stable minor: **Kubernetes 1.37** (see Freshness).

## How to learn Kubernetes well

Start hands-on on day one, on a throwaway local cluster. The official tutorials, LFS158 and the minikube/kind quick starts all converge on the same loop: install `kubectl`, start a one-node cluster (`minikube start` or `kind create cluster`), then run the six "Kubernetes Basics" modules (create cluster, deploy, explore, expose, scale, update) before reading any theory. The Concepts section is written to be read *after* you have watched `kubectl get pods -w` and `kubectl describe pod` react to your own mistakes. The Tasks section is the answer key for "how do I do X"; read it when you have a concrete X. Learn `kubectl describe` and `kubectl logs --previous` early, because the official debugging pages (Debug Pods, Debug Running Pods, Debug Services) all begin there, and the Learnkube flowchart teaches the same bottom-up order: Pod first, then Service, then Ingress.

Common traps the sources warn about: treating the Katacoda in-browser tutorials as current (they stopped in March 2023; the tutorial now assumes a local minikube); reading Kubernetes the Hard Way as a first course (its README says it is "optimized for learning... taking the long route" and is not production-ready, and it is pinned to v1.32); learning Ingress without knowing the project now recommends Gateway API and has frozen Ingress; believing Secrets are encrypted (the Secrets page says they are stored unencrypted in etcd by default); and setting memory limits without understanding OOMKilled and the CrashLoopBackOff backoff schedule (10s doubling to 5 min, reset after 10 min of healthy running). Skip at the start: building a cluster from scratch, CNI internals, CSI driver development, DRA, admission policies and the operator pattern. Pick those up once you can deploy, expose, scale, roll back and debug a stateless app without looking anything up.

## Deck authoring rules

**May be paraphrased with attribution (CC BY 4.0 or more permissive):** every kubernetes.io docs page, kind docs, GKE docs pages carrying the CC BY footer, cncf/curriculum, dgkanatsios/CKAD-exercises (MIT: keep the licence notice in the deck's credits). CC BY-SA sources (walidshaari repos) may be paraphrased only if the deck itself is published CC BY-SA; otherwise use them as reading lists. KTHW text is CC BY-NC-SA: fine for a personal, non-commercial deck, but do not copy prose.

**May only inform original phrasing (no licence or commercial):** Kubernetes Patterns PDF, The Kubernetes Book, Learnkube, Container Solutions, iximiuz Labs tutorials, bmuschko and KodeKloud repos, killer.sh. Read, close the tab, write the card from memory, cite the page as "informed by".

**Source field format:** `<page URL> | Kubernetes docs v1.37 | checked 2026-10-23` for kubernetes.io pages (the docs track the current minor; record the minor you read). For GitHub, pin a commit or tag: `https://github.com/kubernetes/kubernetes/blob/v1.37.1/CHANGELOG/CHANGELOG-1.37.md`. For other sites: `<URL> | <site> | <article date if shown> | checked <date>`.

**Stable URLs:** prefer `kubernetes.io/docs/<section>/<path>/` paths, which have been stable for years; if a card depends on version-specific behaviour, cite `https://v1-3N.docs.kubernetes.io/docs/...` for a released minor (verified for v1-36). Never cite `learnk8s.io` (redirects), `kubebyexample.com` (redirects to the Red Hat home page) or `iximiuz.com` (redirects to labs).

## Freshness

- Current minor on 2026-10-23: **1.37** (latest patch 1.37.1, 2026-09-15); 1.36 and 1.35 also supported; 1.34 reaches EOL 2026-10-27; 1.38 is in development (CHANGELOG-1.38.md already exists). Source: https://kubernetes.io/releases/.
- Before writing any `apiVersion`, flag or feature on a card, check https://kubernetes.io/docs/reference/using-api/deprecation-guide/ (removed APIs per release) and https://kubernetes.io/docs/reference/using-api/deprecation-policy/ (lifetime rules). Feature-gate stages change between minors (for example `KubeletCrashLoopBackOffMax` is beta since 1.35, `ReduceDefaultCrashLoopBackOffDecay` alpha since 1.33), so state the minor on any card that mentions one.
- Exam curricula lag the release: CKA/CKAD are at v1.37, CKS at v1.34 (https://github.com/cncf/curriculum). Kubernetes the Hard Way is at v1.32.

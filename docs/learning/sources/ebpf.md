# eBPF — curated sources

Verified 2026-10-23: every URL below was opened that day. docs.kernel.org renders as 7.3.0; latest release is 7.2. YouTube could not be opened here, so talk links are cited through the pages that publish them.

## 1. How to learn eBPF well

Use eBPF before writing it. Brendan Gregg's tracing guide is explicit: beginners run existing bcc tools (execsnoop, opensnoop, biolatency) with no coding, intermediates move to bpftrace one-liners, and only then do you write tools. Do the bpftrace one-liner tutorial (12 lessons from `bpftrace -l` to reading kernel structs) on a machine you can break, then read the bpftrace language and stdlib references. For compiled programs go straight to libbpf with CO-RE and a `vmlinux.h`: libbpf-bootstrap's `minimal` then `bootstrap` teach the open/load/attach/teardown lifecycle, skeletons, ring buffers and read-only config globals; Nakryiko's CO-RE posts and the libbpf overview explain why this replaces bcc-style runtime compilation. Go developers follow the same path with cilium/ebpf (bpf2go), Rust developers with Aya.

Use a recent kernel with BTF: `/sys/kernel/btf/vmlinux` must exist (`CONFIG_DEBUG_INFO_BTF=y`, pahole >= 1.16, clang >= 11 per libbpf-bootstrap). 6.6 LTS or newer avoids most friction; 5.15 LTS works but lacks TCX links and open-coded iterators. Three recurring traps: verifier rejections (read the log bottom-up, bounds-check against `data_end`, NULL-check every map lookup, keep loops bounded; the budget is 1M instructions since 5.2, 4k before); kernel-version drift (helpers and section names arrive in specific releases, so check the bcc kernel-versions table or the docs.ebpf.io timeline first); and lifecycle leaks (programs and maps die with their last file descriptor unless pinned in bpffs or held by a link; before 5.11 you must also raise `RLIMIT_MEMLOCK`).

## 5. Deck authoring rules

**May be paraphrased or briefly quoted with attribution:** ebpf.io (CC BY 4.0), docs.ebpf.io (BSD-2-Clause), libbpf, libbpf-bootstrap, bpftool, cilium/ebpf, bcc, bpftrace, Cilium docs, eunomia tutorial, lizrice/learning-ebpf code. Aya prose is CC BY-SA: cite, do not copy, to keep the deck out of share-alike.

**May only inform original phrasing:** kernel docs and selftests (GPL-2.0), xdp-tutorial (GPL-2.0), bpf-helpers(7) (man-pages copyleft), Nakryiko's and Gregg's blogs, O'Reilly books, Isovalent labs. Explain in your own words and link; never paste sentences, tables or code.

**Source field format:** `<page URL> — <ISO date opened> [— Linux vX.Y when version-bound]`, e.g. `https://docs.ebpf.io/linux/concepts/verifier/ — 2026-10-23 — v5.2+`.

**Stable URLs:** `https://www.kernel.org/doc/html/v6.6/bpf/...` when a card asserts a specific release, otherwise docs.kernel.org; man pages via man7.org; bpftrace via `/docs/release_027/...`; GitHub files by default-branch path (pin a commit if quoting a line).

## 6. Freshness

Cards assume **Linux 6.6 LTS** semantics (TCX links 6.6, open-coded iterators 6.4, `bpf_loop` 5.17, memcg accounting 5.11, ringbuf 5.8, bpf_link 5.7, bounded loops 5.3, 1M verifier budget 5.2). Flag anything newer in the card (netkit 6.7, sched_ext 6.12, verifier diagnostics 7.3). Treat 5.15 LTS as the "older distro" case: no TCX, no open-coded iterators.

Per-feature versions: https://github.com/iovisor/bcc/blob/master/docs/kernel-versions.md (program types, map types, helpers by version; last entries 6.6), https://docs.ebpf.io/linux/timeline/ (v3.18 to v7.2) plus the version tag on each docs.ebpf.io page, and https://kernelnewbies.org/LinuxChanges for the current release. Re-verify URLs before each deck revision; Isovalent book pages already moved once.
